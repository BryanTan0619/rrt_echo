# Retrieval、QA 与评估

## 输入和隔离

建图仅接收视频、模型配置及可选 ASR。QA JSONL 在建图之后读取，以 `video_id` 匹配图的 `source_video_id`。支持选择题与 True/False，`ans` 用于评分，`hallucination_type` 用于分组；都不成为视频事实。

`rrt-echo-qa` 先验证快照 hash 和 acceptance 中的 snapshot ID。未完成视频验收时使用 `passed=false` 与 `--diagnostic`。验收记录不等于逐题严格 support 标注。

## 每题步骤

1. 从题干解析时间范围，以题干和各选项假设召回局部事实。
2. 保留完整事件角色，补齐身份/部位归属和证据闭包，记录缺口与预算省略。
3. 压缩长 ID 为有映射的别名；将图文本送给 reader。超预算时逐步降低召回数量，不能任意裁掉角色字段。
4. 强制选择一个合法选项；即使证据不足也作答。
5. 第二次模型调用审计所选答案的断言。审计不接收标准答案、原始视频或 caption。
6. 校验/还原引用，分别统计答对、图内支持、执行失败。

通常每题两次请求；失败可能减少实际次数。以 `calls.json` 为准，不通过答案数量估计调用数。

## 结果解释

- `accuracy` 以全部题目为分母，执行错误不能从统计中剔除。
- `answer_support` 是图内审计结果；图本身可能写错，不能称为独立视频验证。
- `correct_with_support` 在未完成独立媒体审计时为 null。
- 一个开发视频或一次固定观察的 QA 对照不能证明跨视频泛化。
- 检查逐题 `reader_payload`，区分：视频观察遗漏、局部角色/身份绑定错误、相关证据未召回，以及 reader 使用证据错误。不要仅凭答案错误直接判断损失阶段。

## 复现记录

保留视频 hash、采样配置、模型/服务版本、代码版本、完整观察日志、快照 ID、请求响应和调用清单。`request_inventory.json` 中请求耗时之和可能因并行而大于墙钟时间。

README 的命令是公开 base 使用配置。历史 V30 包含额外四批对应补充和随后固定观察重投影，不应把 README 单条命令宣称为逐字复现历史 20/28 的实验脚本。
